# LM-Router 연구 문서

최종 정리: 2026-09-06 · 상태: 자료조사 및 설계 후보 · 문서 언어: 한국어

## 프로젝트 목적과 현재 제약

- 목적: 사용자 쿼리와 에이전트 실행 상태에 따라 모델을 선택해, 필요한 작업 성공률·답변 품질을 유지하면서 전체 비용을 줄인다.
- 대상: 도구 호출과 여러 모델 호출로 이루어지는 에이전트 작업. 단일 응답 라우팅도 비교 대상으로 다룬다.
- 사용자 확정 제약: **라우터를 별도로 학습시키지 않는 방향으로 연구·구현한다.**
- 핵심 문제: 모델 전환의 이득이 프롬프트 캐시 손실, 추론 상태 호환성, 추가 호출·재시도 비용을 상쇄하는가?
- 현재 상태: 코드 구현·유료 API 실험·자체 벤치마크는 수행하지 않았다. 문서의 설계 후보를 구현 결정으로 간주하지 않는다.

이 조사에서는 우선 수동 규칙과 기존 범용 LLM의 프롬프트 기반 판단을 후보로 포함한다. 후자는 추가 학습이 없지만 추론 비용은 발생한다. 추가 LLM 호출까지 배제할지는 아직 확정하지 않았다. 과거 정답·선호도 데이터에 의존하는 비신경망 방식은 별도 분류한다.

## 최신 조사 결론과 바로가기

**일반적인 ‘무학습 + 대화 맥락 + 캐시 유지’ 조합은 이미 선행연구·구현이 있다.** 기존 실행 계층 위에서 정책을 구현하는 것은 가능하지만, 현 프로젝트가 더 낫다는 실측 근거는 아직 없다. 모델별 캐시 상태·남은 단계 불확실성·판정 비용을 함께 다루는 좁은 가설을 우선 검증하는 것이 현재 권고다.

## 문서의 역할

- `research/`: 논문·공식 문서·공개 코드에서 관찰한 사실과 그 한계.
- `design/`: 이 프로젝트에 대한 설계 제안. 승인된 구현 명세가 아니다.
- `evaluation/`: 앞으로 실행할 비교 실험. 실험 결과와 혼동하지 않는다.
- `references/`: 원문 링크, 식별자, 확인일, 코드 스냅샷. 출처의 기준 위치다.

본문의 `Pxx`는 논문, `Rxx`는 공개 구현, `Dxx`는 공식 제품·API 문서를 뜻한다. 출처에서 확인한 사실, 저자·업체의 주장, 이 프로젝트의 제안을 구분한다. 서비스 문서는 공개 동작의 근거이며, 서비스의 독립적인 성능 검증은 아니다.

조사 보강: 사용자가 제시한 **Switchyard와 Weave Router**를 출발점으로, **vLLM Semantic Router·Bifrost·Otari**까지 확인했다. 선택 주기·stage 정책은 Switchyard, 명시적 경제성은 Weave, session/cache/tool 보호는 vLLM을 가까운 비교군으로 본다. 추천기와 전환 정책의 학습 조건을 분리하며 [구현 재사용 계획](design/implementation-reuse-plan.md)의 현재 연결 경로를 우선 확인한다.

추가 방법론 조사: [별도 비교 문서](research/alternative-routing-methods.md)에 semantic 예시 경로, kNN utility, CP-Router, CARGO, Smoothie(-Train), BoundaryRouter, AutoMix를 정리했다. Augment Prism의 사용자 턴 내 고정 사례도 추가했다. **라벨 없음·신경망 학습 없음·정책 보정 없음은 별개의 조건**으로 유지한다.

## 용어

| 용어 | 이 문서에서의 의미 |
|---|---|
| 작업 / episode | 사용자 요청 하나를 완료하거나 실패·중단할 때까지의 전체 실행 |
| 단계 / step | 라우터가 개입할 수 있는 한 번의 모델 생성 요청 |
| 도구 호출 | 모델이 요청한 외부 함수 실행. 한 단계에서 여러 개 발생할 수 있음 |
| 세션 | 여러 작업을 포함할 수도 있는 대화·실행 식별자. episode와 별도로 기록 |
| 모델 라우팅 | 서로 다른 모델 중 적합한 모델 선택 |
| 제공자·인스턴스 라우팅 | 선택한 모델을 어느 제공자·배포 서버에서 실행할지 선택 |
| 프롬프트 / prefix / KV 캐시 | 이전 입력의 계산 상태를 재사용. 새 응답은 생성함 |
| 응답 / semantic 캐시 | 이전 응답 자체를 재사용. 프롬프트 캐시와 다른 문제 |

## 후속 작업자가 지킬 사항

1. 최신 판단인 `research/novelty-and-feasibility.md`, `design/implementation-reuse-plan.md`와 `design/router-options.md`의 미결정 사항·사용자 제약을 먼저 읽는다.
2. 가격·모델 지원·캐시 TTL·제공자 동작은 구현 시 공식 문서에서 다시 확인한다.
3. 새 출처는 `references/sources.md`에 먼저 등록하고 관련 주제 문서에서 연결한다.
4. 기존 결과를 수정할 때 논문 버전·벤치마크 범위·측정 조건을 함께 갱신한다.
5. 자체 실험 결과가 생기면 별도 결과 문서에 실행 설정·버전·원시 로그 위치를 남긴다. 계획 문서의 예상치를 실측치로 바꾸어 쓰지 않는다.
